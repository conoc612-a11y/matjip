# 맛집 탐방 🍜 + 부동산 투자자 지도 🏙️

서울 맛집을 취향 기반으로 추천받고 지도·길찾기로 찾아가는 서비스 + 부동산 투자자를 위한 원격 임장 지도.

## 화면
- `index.html` → `onboarding.html` : 로그인/회원가입 + 취향 온보딩 설문 → `taste_profiles` 저장
- `main.html` : 맛집 지도(Leaflet + V-World/OSM) + 취향 기반 규칙 추천 + 저장 + GPS 길찾기
- `ai.html` : 자연어로 취향 입력 → 키워드 파싱 → 추천
- `detail.html` : 맛집 상세 + 저장/관심 + 대중교통(ODsay)/도보·자차(OSRM) 길찾기
- `land.html` : **부동산 투자자 지도** (아래 기능 참고)

## land.html (부동산 투자자 지도)
- **실거래가 레이어** — 아파트(서울+경기 9천여 단지)·연립/다세대(서울 23,708건) 클러스터링, 필터·범례·카드 팝업
- **건축물대장** — 국토교통부 건축HUB(data.go.kr, Supabase Edge Function 프록시): 공시지가·지번·용도지역·노후도·호실별 면적
- **정비사업** — 서울 재개발·재건축 등 1,100여 구역 폴리곤(정보몽땅), 진행 단계별 필터, 구역 커뮤니티(Supabase `jb_posts`)
- **정비사업 취소구역(모아타운·신통기획)** — 2026-08-04 서울시 발표로 취소구역 정보 전면 공개(정보몽땅 취소현황 게시판 신설, 8/5 시행). Open API 없음, 스크래핑 수집 계획 — `API 정보.txt` §7 참고
- **투자 도구** — 즐겨찾기·비교, 인근 공인중개사(카카오), 전반기/후반기 실거래 상승률 랭킹(자체 계산)
- **검색** — V-World(JSONP)·카카오 장소검색, 역지오코딩, 단지명 축약 보정
- 데이터 현황·API 활용 계획은 `API 정보.txt` 참고

## 기술
- **DB/인증**: Supabase (Postgres + Auth 이메일 검증), RLS로 본인 데이터만 접근
- **지도**: Leaflet + V-World 타일 (키 없으면 OSM 자동 대체)
- **길찾기**: 앱 내부 — 대중교통(ODsay) · 도보/자차(OSRM) · 카카오맵 딥링크
- **공공 데이터**: data.go.kr 실거래가·건축물대장 수집(`tools/collect_realprice.js`), 정적 JSON 시드
- **금융 데이터**: 한국수출입은행 환율·대출금리·국제금리(`oapi.koreaexim.go.kr`, 서버 전용 키 — `API 정보.txt` §6)
- **프론트**: 정적 HTML/JS, 빌드 도구 없음 · GitHub Pages 배포

## DB (5테이블)
`profiles`(auth 확장) · `taste_profiles` · `mj_restaurants` · `saved_restaurants` · `feedbacks`
(+ 정비구역 커뮤니티 `jb_posts`) — 스키마·RLS·시드는 `schema.sql` (Supabase SQL Editor에서 실행).

## 로컬 실행
정적 파일이라 브라우저로 `index.html`을 열면 됩니다.
(GPS·V-World 지도·Supabase Auth는 https/localhost에서 동작 — 배포 환경 권장)

## 설정 메모
- V-World 지도: `main.html`/`detail.html`/`land.html`의 `VWORLD_KEY`에 vworld.kr 발급 키 입력(도메인 등록 필요).
- 건축물대장: `supabase/functions/molit-proxy`에 data.go.kr 인증키 환경변수 설정.
- 수은 환율/대출금리/국제금리: `keys.env`의 `EXCHANGE_RATE_KEY`/`LOAN_RATE_KEY`/`INT_RATE_KEY` → Supabase Edge Function secret(`supabase secrets set`)으로만 사용, HTML 하드코딩 금지.
- 이메일 검증: 배포 후 Supabase Authentication에서 Confirm email ON + Site URL을 배포 주소로 설정.
- 클라이언트에 노출된 키는 publishable(anon) 키로 공개 안전 — 접근 제어는 RLS가 담당.

## 정비사업·신속통합기획 데이터 — 사이트 3곳 조사 결과 및 개선 제안 (2026-08-05)

서울시 사이트 3곳(서울도시공간포털 urban.seoul.go.kr / 정비사업 정보몽땅 cleanup.seoul.go.kr / 도시건축 뉴스 news.seoul.go.kr/citybuild)의 아키텍처·데이터 소스를 실측 조사. 세부 API·URL·응답 형식은 `API 정보.txt` §8(ArcGIS·bsns API)·§9(뉴스 RSS) 참고. 아래는 matjip 입장의 개선 제안.

### 현재 matjip 정비사업 데이터 한계
- `redevelop_seoul.json` 1,137건은 **수동 시드** — 정보몽땅 사업검색에서 수집했으나 **신속통합기획은 사업명 regex(`/신속통합기획|신통|통합구역/`)로만 구분** (land.html `jbGroup()`). 실제 신통기획 227건 중 상당수가 '재개발' 등으로 오분류될 수 있음.
- `redevelop_polygons.json` 폴리곤은 중복 링·퇴화 링이 섞여 land.html이 정제 코드(`usableRings`)로 가공 중. **기준일(갱신일)이 없어 구역이 계속 바뀌어도 추적 불가.**
- 진행단계(stage)는 스냅샷 텍스트 — **단계별 이력(언제 사업시행인가를 받았는지)이 없어 투자자가 진행 속도를 판단 못 함.**

### 개선 제안 (우선순위순)
1. **신통기획 전용 데이터로 교체·보강** — 서울도시공간포털 ArcGIS WFS 레이어 94(`UPIS_C_UQ120_BZ101`) 1회 조회로 신통기획 227건 전체 확보(기획완료 132 + 추진중 95). 코드(BZ101)로 정확 분류 → matjip의 regex 분류를 대체. (`API 정보.txt` §8 경로 C)
2. **정비구역 전체 폴리곤 자동 갱신** — UQ120(L12) 덤프(2,964건, 18.7MB) 1회 수집 → 사업명·자치구로 cleanup 목록과 조인해 `redevelop_seoul.json`·`redevelop_polygons.json` 재생성. `outSR=4326` 결과는 그대로 WGS84(네이버 지도 호환)라 변환 불필요. (§8 경로 B)
3. **추진단계 이력·담당부서 노출** — 통합검색 API(`/api/srch/integrated.json`)의 `tnBsnsPropels[]`(단계+날짜)와 담당부서/연락처를 land.html 카드에 추가 → 투자자가 "얼마나 오래 끌리는 구역인지" 판단 가능. (§8 경로 A)
4. **신통기획·모아타운 뉴스 피드** — 도시건축 뉴스 RSS(신통기획 태그 226건, 모아타운은 검색 피드)를 Supabase Edge Function RSS 프록시로 수집, 구역 카드에 최신 소식 노출. (README `설정 메모`의 `molit-proxy` 패턴 재사용, §9)
5. **취소구역 연동** — 2026-08-04 서울시 발표(취소구역 정보 공개, 8/5 시행)에 따른 취소현황 수집은 §7 계획. 신통기획·모아타운 취소구역이 생기면 1·2번 데이터와 대조해 리스크 표시.
6. **경계지도·정보공개 링크 유지** — land.html이 이미 urban.seoul.go.kr `mapPopup`(recordCode)과 cleanup `cafe`로 연결 중. §8의 `PRESENT_SN`(신식 recordCode)으로 갱신 가능.

### matjip에 데이터를 넣는 실제 작업 (할 때)
1. 조사 결과 기반 **수집 스크립트 작성**(`tools/collect_redevelop.js` 신설 — `tools/collect_realprice.js` 패턴) → urban proxy/bsns API 호출 → JSON 시드 재생성.

3. 뉴스 피드는 Edge Function 추가(또는 기존 프록시 확장) → 주기 수집 → 정적 JSON.
4. 취소구역 게시판 실물 확인 후 §7 A안 구현.

## 정비사업 데이터 개편 — UQ120 전환 + UI 대분류 개편 (2026-08-05, `improve/redevelop-data` 브랜치)

- **UI 대분류 개편**: `urban.seoul.go.kr` 메뉴 구조(대분류→중분류 2단)를 참고해 `land.html`/`js/main.js`의 `JB_SEC`를 정비/소규모/역세권/국토부·기타 4대분류로 재구성.

- **검증**: puppeteer/브라우저 자동화로 줌 인·아웃 시 폴리곤 재렌더(뷰포트 필터), 메뉴 스크롤이 지도 줌으로 새지 않음(`disableScrollPropagation`), 데스크톱·모바일 양쪽에서 패널이 화면 안에 들어옴을 확인. JS 문법·HTML 태그 균형·`land.html`↔`main.js` 로직 동기화 확인.

### 배경지도 선택 UI + 폴리곤 정확도 조사 (2026-08-05)

- **배경지도 선택 UI**: 좌상단에 '항공' 토글 버튼 하나만 있어 어떤 지도가 있는지 알 수 없었다. 네이버지도처럼 **썸네일 3종(일반지도/위성지도/위성+라벨)** 을 나란히 보여주는 `.bm-picker`로 교체. 썸네일 배경은 서울 도심(z15) 실제 V-World 타일이라 별도 이미지 파일이 필요 없다.
- **폴리곤 정확도 조사 결과 — 데이터는 정확함**: "폴리곤이 지도와 안 맞는다"는 지적을 검증하기 위해 재개발닷컴(네이버 위성지도) 위에 matjip의 봉천14 폴리곤(`11620UQ120PS202607220001`)을 그대로 겹쳐 그린 결과 **재개발닷컴 폴리곤·위성사진 구역 경계와 픽셀 단위로 일치**했다. 함께 확인한 것:
  - matjip 저장 중심좌표를 재개발닷컴 지도에 찍었을 때 그들의 구역 마커와 정확히 일치
  - V-World 타일과 OSM 타일을 같은 z/x/y로 받아 비교 → 동일 영역, 좌표계 오프셋 없음
  - `usableRings()`는 링 필터링만 하고 좌표를 변형하지 않음
- **적용한 개선**: `smoothFactor` 2 → 1. Leaflet의 화면픽셀 기준 단순화 허용오차로, 줌 17에서 경계 이탈이 **최대 2.43m → 0.95m**로 줄었다(실측). 미세하지만 고배율에서 필지선과의 어긋남이 줄어든다.
- **미해결**: 위 검증으로는 사용자가 본 어긋남을 재현하지 못했다. 특정 구역에서 재현되면 그 구역의 `rc`(PRESENT_SN)로 다시 조사할 것.

### 팝업 줌 재배치 버그 수정 (2026-08-05)

건물 클릭 팝업이 지도 확대·축소 후 화면 밖으로 잘리던 버그. `zoomend` 핸들러가 팝업 높이를 조정하려고 바깥 `.leaflet-popup` 래퍼에 인라인 스타일을 넣고 있었는데, 실제 높이 제한은 안쪽 `.leaflet-popup-content`가 CSS 변수(`--popup-max-h`)로 담당해 그 조작은 죽은 코드였다. `repanPopup()`에 픽셀 기준 정밀 판정(`precise` 옵션)을 추가해 줌 직후에만 적용 — 비동기 상세 조회 렌더 시 지도가 순간이동하던 과거 회귀(커밋 `3e02fdb`)를 막던 기존 좌표 기준 판정은 그대로 유지. 상세: `HANDOFF.md`.

### 참조 사이트 주제도 전체 이식 + UI 정리 5건 (2026-08-06)

서울도시공간포털의 주제도를 **같은 ArcGIS 서비스를 그대로 붙여** 구현했다. 데이터를 따로 받아 가공하지 않으므로 기호·라벨·minScale 동작이 그쪽과 동일하다.

- **UPIS 주제도 7종 추가**: 지구단위계획구역 / 용도지구 / 용도구역 / 도시계획시설 / 가로구역별 건축물 높이기준 / 기후환경 공간유형 / 생태현황도(2025). `L.TileLayer` 를 상속해 타일마다 ArcGIS `/export` URL 을 만든다. MapServer 가 http 라 https 페이지에서 직접 못 부르고 서울시 공개 프록시를 탄다(브라우저에서 이미지 로드 실측 확인). 레이어 id 는 `?f=pjson` 목록에서 뽑아, 묶음별로 export 를 호출해 빈 이미지(2.2KB)와 비교하며 실제로 그려지는지 검증했다.
- **레이어 메뉴 8개 대분류**로 재편, 순서도 정의대로 고정: 도시계획사업 / 도시계획(서울) / 규제구역 / 주제도 / 실거래 / 현장 확인 / 용도·지적 / 행정경계.
- **배경지도를 오른쪽 목록에서 제거**했다. 좌상단 썸네일 버튼으로 이미 고르는데 같은 선택지가 두 군데 있어 헷갈렸다(`L.control.layers(null, …)`).
- **줌(+/−) 버튼 높이를 배경지도 피커에 맞췄다.** 기본 26px×2 라 피커(87px)보다 짧아 피커만 아래로 튀어나왔다 → 줌 컨트롤을 flex 로 늘려 각 버튼이 절반씩 차지하게 했다(실측 87px = 87px).
- **공인중개사 카드 버튼 줄바꿈 수정**: 전화번호·카카오맵·저장 3개가 좁은 패널에서 '저 장' 처럼 글자가 접혔다 → 글자는 `nowrap`, 줄바꿈은 버튼 사이에서만(`flex-wrap`).
- **팝업 크기 조절 가능**: 고정 크기라 답답하다는 지적에 `resize: both` 추가(우하단 모서리 드래그). `overflow` 를 `auto` 로 바꿔야 동작한다.

### 참조 사이트 방식 도입 — 허가구역은 외곽선만·줌 제한, 레이어 메뉴 대분류화 (2026-08-06)

서울도시공간포털(urban.seoul.go.kr)이 같은 데이터를 어떻게 보여주는지 확인하고 그대로 맞췄다. 그쪽의 ArcGIS export 를 직접 호출해 렌더링 결과를 확인한 결과:

- **채우기를 아예 안 한다.** 얇은 주황 외곽선 + 라벨만 그린다. 그래서 자치구 전역 지정(서초 46.9㎢·강남 39.5㎢ 등)이 한강을 가로질러도 얇은 선만 보이고 강이 색칠되지 않는다. matjip 도 `fill: false` 로 바꿨다 — 앞서 "채운 뒤 강을 오려내는" 방식으로 씨름한 건 애초에 필요 없는 문제였다.
- **`minScale: 50000`** — 축척 1:50,000 보다 축소하면 레이어를 아예 안 그린다. 서울 전역이 한 화면에 들어오는 축척에서 구역선이 도시를 뒤덮는 걸 막는 장치다. matjip 은 Leaflet 줌 14 미만에서 숨기도록 맞췄다(줌 14 ≈ 1:35,000, 13 ≈ 1:70,000).
- **레이어 메뉴를 대분류로 묶었다.** 참조 사이트의 '주제도'가 대분류 > 중분류로 정리돼 있어, 12개가 한 줄로 늘어선 기존 목록보다 훨씬 찾기 쉽다. 도시계획사업 / 현장 확인 / 실거래 / 규제구역 / 행정경계 / 용도·지적 6개 그룹. Leaflet 기본 컨트롤엔 그룹 기능이 없어 DOM 에 헤더를 끼워 넣는 방식인데, Leaflet 이 레이어 토글마다 `_update()` 로 목록을 통째로 다시 만들기 때문에 **`_update` 를 감싸 갱신 후마다 헤더를 다시 적용**해야 한다(안 그러면 첫 체크에 헤더가 사라진다).

### 토지거래허가구역 — 동 단위 근사 → 실제 경계 + 한강 제외 (2026-08-06)

"허가구역 폴리곤이 부정확하고 한강에도 칠해진다"는 제보를 고쳤다.

### 배경지도 4종을 줌 버튼 옆으로 + 팝업 줌 재배치 완전 수정 (2026-08-05 심야)

이전에 "반영했다"고 기록했지만 실제로는 안 들어갔던 항목들을 마무리했다.

- **배경지도 선택 UI 위치·항목**: 줌(+/−) 버튼 바로 오른쪽에 나란히 붙였다. Leaflet 은 같은 코너에 넣은 컨트롤을 세로로만 쌓으므로, 줌 컨트롤과 피커를 `.ctl-row` 한 줄로 감싸 가로 배치로 바꿨다(코너 컨테이너 자체는 정비사업 메뉴 스크롤 때문에 flex column 유지). **OSM 을 4번째 선택지로 추가** — 그전엔 V-World 장애 시 자동 대체용으로만 쓰여 수동 선택이 불가능했다. 좁은 화면에서는 썸네일을 52px로 줄여 가로 넘침을 막는다.
- **팝업이 줌·내용 갱신에 맞춰 재배치되지 않던 버그 (진짜 원인 규명)**: 앞선 커밋(`bc66a95`)으로 부족했던 이유는 두 가지였다.
  1. Leaflet 의 `_adjustPan()` 에는 `_autopanning` 플래그가 있어 "직전에 자동 패닝했으면 이번 호출은 통째로 건너뛰고 플래그만 리셋"한다. 팝업이 열릴 때 한 번 패닝되므로 그 다음 줌에서의 호출이 삼켜져, 줌해도 팝업이 지도 위쪽으로 잘린 채 남았다(실측 top −52px, 모든 줌 레벨 동일). → 플래그 없이 '실제로 잘렸는지'만 보고 최소 거리로 `panBy` 하는 구현으로 `_adjustPan` 을 통째로 교체.
  2. 상세 내용(토지·건물 정보, 인근 상호)은 `update()` 가 내용을 지우는 것을 피하려 **팝업 DOM 에 직접 주입**하는데, 그래서 `update()` 가 부르는 `_adjustPan` 이 아예 안 불렸다. → 그 주입 지점들에서 직접 정밀 재배치를 호출.
  - ResizeObserver 로 잡으려는 시도는 실패했다 — `--popup-max-h` 에 걸리면 컨테이너 크기가 더 이상 변하지 않아 콜백이 0회다(실측). 기록만 남기고 제거.
  - 검증: 새 지점 클릭 시 상세 로드 완료 후 top 104(지도 상단 92 + 여백 12), 줌 12/19/15/17 왕복 전부 지도 안에 들어옴.
- **참조 사이트 대조**: 서울도시공간포털은 `.esri-popup__main-container { max-height:300px }` + 내용부 `overflow:auto` 로, "고정 최대높이 + 내부 스크롤" 방식이다. matjip 은 이미 같은 구조를 쓰되 고정 300px 대신 지도 높이의 62%(`--popup-max-h`)라 오히려 더 반응형이다. 즉 문제는 높이가 아니라 위치였고, 위 두 가지가 원인이었다.

### 헤더 날씨·환율 위젯 구현 완료 / CCTV는 IP 차단으로 미동작 (2026-08-05 심야)

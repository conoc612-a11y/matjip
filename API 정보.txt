# 부동산 투자자용 "원격 임장" 서비스 — data.go.kr API 활용 정리

## 1. 서비스 방향

투자자가 실제 임장(현장 방문) 없이 의사결정에 필요한 정보를 지도 위에서 한눈에 확인하는 서비스.

- 임장 전 사전 조사: 인근 식당·관공서·편의시설·대중교통·주차장
- 투자 판단 데이터: 실거래가·공시지가·전월세·청약·정비사업·지가변동률
- 현장 화면: 실시간 CCTV + 거리뷰로 원격 확인
- 임장 중 사고 대응: 낯선 지역에서 분실한 물건·핸드폰 찾기

### A. 이미 연동·활용 중 (그대로 유지)

## 3. 부동산 투자자가 실제로 필요한 정보

원격 임장 서비스 기준, 의사결정 축별로 필요한 정보와 데이터 커버리지.

### 3-1. 시세 / 가격
- [있음] 매매 실거래가 (아파트·연립·단독·오피스텔)
- [있음] 공시지가 (건축물대장 연동)
- [연동가능] 전월세 실거래가 → **전세가율** 계산 (투자 판단 핵심)
- [연동가능] 지가변동률 → 가격 추이
- [추가 필요] 월세/보증금 시세 (오피스텔 전월세로 일부 커버)

### 3-2. 수익성
- 전세가율 = 전세가/매매가 (갭투자·가격 하방 지지 판단)
- 월세 수익률 = 연월세/매매가 (오피스텔·빌라)
- 경쟁률 (청약 수요 신호)
- [미지원] 공실률·관리비·공동주택 재정 (공동주택 기본정보로 일부)

### 3-3. 입지 / 교통 / 주변 인프라 (임장 대체)
- [연동가능] 지하철역·버스정류장 거리 — 카카오 Places 키워드 검색
- [연동가능] 인근 식당·카페·마트·병원·약국 — 카카오 Places
- [연동가능] 관공서(구청·주민센터·경찰서·소방서) — 카카오 Places
- [연동가능] 주차장 — 서울 열린데이터광장 공영주차장 (data.go.kr엔 미신청)
- [연동가능] 전기차 충전소 — 신청 완료
- [미지원] 대중교통 실시간 위치 — 서울 열린데이터광장

### 3-4. 리스크 / 규제
- [연동가능] 토지이용규제 (용도지역·지구·투기과열지구·조정대상지역)
- [있음] 정비사업 구역 (재개발·재건축 진행 현황)
- [있음] 건물 노후도·용도·지적 (건축물대장)
- [미지원] 재난·범죄 안전 정보 (경찰청 범죄통계는 분실물 API와 별개 — 별도 신청 필요)
- [미지원] 공실·미분양 현황

### 3-5. 개발 / 공급
- [연동가능] 청약 분양정보 → 분양예정 배지
- [연동가능] 청약 경쟁률 → 수요 분석
- [미지원] 신규 공급 계획·택지개발지구 (토지이용규제로 일부)

### 3-6. 현장 화면 (임장 대체)
- [지원] 지적도·용도지역 폴리곤 (건축물대장·정비사업 데이터로 그리기)
- [지원] 기상청 CCTV — **실시간** 도로 화면. 로드뷰(정적 사진)의 실시간 한계를 보완
- [지원] 네이버·카카오 로드뷰 링크 — 정적 스냅샷이지만 근접 상세 확인
- **운영 제안**: 실시간이 필요한 화면(교통·날씨·현장 상황)은 CCTV, 고정된 상세 확인은 로드뷰 — 두 개를 상호 보완해 연동

## 5. 정리

- **즉시 효과**: 청약 분양정보·경쟁률·토지이용규제·전월세 4종 연동이 투자자 서비스의 80%를 완성함.
- **임장 대체 핵심**: 주변 편의시설/관공서/교통은 data.go.kr보다 **카카오 Places**가 유리 (이미 main.html·land.html 사용 중).
- **실시간 vs 정적**: 거리뷰(로드뷰)는 정적 사진, 기상청 CCTV는 실시간 도로 화면 — 서로 다르므로 **둘 다 필요**. 로드뷰로 상세 확인, CCTV로 실시간 상황 확인.
- **경찰청 유실물 4종**: 낯선 지역 임장 중 분실 대응용 안전 기능으로 활용. 신청 3건 승인 대기.
- **빠진 데이터**: 학군·병원·범죄통계·공영주차장·실시간 대중교통은 4번 섹션 목록으로 추가 신청 필요.

## 6. 금융 환경 데이터 — 한국수출입은행 환율·대출금리·국제금리 (발급 완료)

data.go.kr과 별개로, 한국수출입은행 Open API(수은, oapi.koreaexim.go.kr)를 직접 신청해 **인증키 발급 완료**(keys.env 저장). 부동산 투자 의사결정의 매크로 환경 지표로 활용.

### API 3종 (동일 엔드포인트, `data` 파라미터로 구분)
| data | API | keys.env | 용도 |
|---|---|---|---|
| AP01 | 현재환율 | `EXCHANGE_RATE_KEY` | 환율 변동 — 외화·해외 투자 환경 |
| AP02 | 대출금리 | `LOAN_RATE_KEY` | 레버리지 비용 — 갭투자·대출 의사결정 (핵심) |
| AP03 | 국제금리 | `INT_RATE_KEY` | 해외 금리 환경 |

### 연동 방식 (서버 전용)
- **키는 서버 전용** — HTML/JS 하드코딩 금지. `keys.env`에만 기록하고 Supabase Edge Function 프록시(`molit-proxy` 패턴)로만 호출.
  - 배포: `supabase secrets set EXCHANGE_RATE_KEY=<...> LOAN_RATE_KEY=<...> INT_RATE_KEY=<...>`
- 엔드포인트:
  ```
  https://oapi.koreaexim.go.kr/site/program/financial/exchangeJSON?authkey=<인증키>&searchdate=YYYYMMDD&data=AP01|AP02|AP03
  ```
- 응답: JSON 배열 (result: 1 성공 / 2 DATA코드 오류 / 3 인증키 오류·키 파기 / 4 일일 제한 초과). 환율은 영업일 11시 전후 갱신, 주말·공휴일은 빈 배열 → 직전 영업일로 재요청.

### 주의사항
- **도메인 변경**: 기존 `www.koreaexim.go.kr`은 2026.4.30 종료. 신규 `oapi.koreaexim.go.kr` 사용.
- 일일 호출 1,000회 제한.
- 개인정보 보유기간 2년 만료 시 키 자동 파기(RESULT 3) — 만료 전 이메일 재동의 필요, 파기된 키는 재발급만 가능.

### 상태
인증키 3종 발급 완료(keys.env 기록) · Edge Function 연동 대기. 연동 시 대출금리를 land.html 투자 카드에 '금리 환경' 지표로 노출하는 방향.

## 7. 정비사업 취소구역 (모아타운·신통기획) — 조사결과 및 수집 계획

### 개요 (2026-08-04 서울시 발표, 08-05 시행)
- 모아타운·신통기획 **후보지 취소(해제·철회)구역 정보 전면 공개**. 후보지 단계는 고시 의무가 없어 사업 철회 후에도 "개발 예정지"로 오인되는 허위 매물·거래 혼선을 차단하려는 조치.
- 공개 채널 3곳: ① 정비사업 정보몽땅 취소현황 게시판(신설) ② 자치구 누리집·구보 ③ 공인중개사는 매물 등록 전 서울시/자치구에 구역 현황 확인 의무. 취소구역 내 현수막·벽보 즉시 철거.

### API 공개 여부 (조사일: 2026-08-05)
- **정보몽땅 자체에 공식 Open API 없음** — 게시판·사업검색·고시/공고 기반 포털.
- **취소구역 전용 Open API 미출시** — 검색상 데이터셋 개방 계획도 없음.
- 유일한 정비사업 Open API: 서울 열린데이터광장 **"서울시 도시계획 정비사업 현황"(OA-20281)** — 일반 정비사업(재개발·재건축 등) 현황이며 취소구역 별도 필드 없음.
- **취소현황 게시판 실물 미확인**: 신설(8/5) 직후라 게시물이 아직 없음. bbsClCode 100~2900 전수 스캔에도 "취소현황" 텍스트를 포함한 게시판이 안 잡힘 → 메뉴·게시판 코드 아직 등록 전일 가능성.

### 수집 계획 (A안 — 스크래핑, 임시 수단)
정보몽땅은 JSP 게시판 시스템(lscr.do=목록 / vscr.do=상세, 파라미터 bbsClCode·cpage·searchCode·searchValue·nttSn), 서버렌더링 HTML, 로그인 없이 GET 조회 가능(공지사항 목록 직접 조회로 확인). 취소현황 게시판 URL 확정이 선행 과제.
1. **게시판 발굴**: bbsClCode 재스캔 / 통합검색(`datasearch`)에서 "취소" 검색 / 신속통합기획 페이지 메뉴 확인. 실물 없으면 B/C안으로 보류.
2. **목록 크롤링**: `lscr.do?bbsClCode=XXX&cpage=N` 순회 → 제목·날짜·`nttSn` 추출 (단순 GET+HTML 파싱).
3. **상세 크롤링**: `vscr.do?...&nttSn=...` 접근 → 본문·첨부 수집.
4. **첨부파일 파싱**: hwp(`olefile`+`hwp5txt`)·xlsx·pdf → 구역명·자치구·위치·취소사유·취소일 추출.
5. **정제·저장**: 주소 → V-World/카카오 지오코딩 → Supabase 테이블(예: `cancelled_areas`) 저장 → land.html 정비사업 레이어에 통합.
6. **주기**: 일 1회 증분(마지막 `nttSn` 이후만).

### 한계
- 주력 데이터가 게시판 **첨부파일(HWP/PDF)** 형식 → 파싱 품질 이슈, 좌표가 텍스트면 지오코딩 오차.
- 서울시가 데이터셋(Open API)을 출시하면 크롤링 불필요 → **A안은 임시 수단**.
- 게시판 실물 미확인 상태라 당장 코딩 불가.

### land.html 활용 제안
- 정비사업 레이어에 **취소구역 상태 필터** 추가 (구역명 매칭 우선, 폴리곤 보정은 후순위).
- 취소구역 내 매물/즐겨찾기에 "취소구역" 리스크 경고 배지.

## 8. 정비사업 구역 폴리곤 확보 — 서울도시공간포털(urban.seoul.go.kr) ArcGIS 실증

### 핵심 결론 (2026-08-05 실증)
- **cleanup.seoul.go.kr(정보몽땅)에는 폴리곤/지도 데이터가 없다.** 사업검색 목록(`lsubBsnsSttus.do`)은 자치구·사업구분·사업장명·대표지번·진행단계만 제공하고 행 단위 지도 링크·recordCode 미포함. mainMap.do는 404.
- 구역 폴리곤의 원본은 **서울도시공간포털(urban.seoul.go.kr)의 UPIS ArcGIS 서버**(구 map.seoul.go.kr/smgis)다. 지도 화면(`/view/map/main.html`, `/content/map/*.js`)이 ArcGIS REST로 구역을 그린다.
- 내부 ArcGIS 서버(`http://98.33.2.225:6080/arcgis/`)는 직접 접근 시 타임아웃이지만, **공개 프록시로 전체 조회 가능**:
  `https://urban.seoul.go.kr/proxy/proxy.jsp?<내부 ArcGIS URL>`
  (프록시 URL의 `?`는 리터럴로 연결. `%3F`로 인코딩하면 실패. `where=1%3D1`처럼 파라미터는 표준 인코딩 그대로)

### 경로 A (권장) — 통합검색 API (사업명 → 전체 정보 + 폴리곤)
- `POST https://urban.seoul.go.kr/api/srch/integrated.json`, Content-Type `application/json; charset=UTF-8`
- body:
  ```json
  {"searchMode":"map","searchGubun":"mapSearch","classifyType":"bsns",
   "keywordList":["상록수"],"pageNo":1,"pageSize":5}
  ```
- 응답: 사업유형 그룹별(BZ100~BZ600) 페이지. 항목의 핵심 필드:
  - `upisCUq120`: UQ120 레코드 전체 — `presentSn`(예: `11680UQ120PS202607300001`), `dgmNm`(사업명), `dgmAr`(구역면적 ㎡), `signguSe`(자치구코드), `sclasCl`/`atrbSe`(사업유형 BZ101 등), `propelCd`, **`shape`(폴리곤)**
  - `tnBsnsPropels[]`: 추진단계 이력 — `propelDt` + `propelCdNm`(실측: PP0201=입안제안, PP0204=구역지정, PP0103=기획완료) + `propelGrpNm`(추진중/완료)
  - `tnBsnsDataStnd`: 데이터 기준일(`rfencDt`)·담당부서/담당자/연락처
  - `tnBsnsCodeRgn`: 권역(실측: TY0205=동남권)
- 실측: 키워드 "상록수" → BZ100 그룹 2건. ArcGIS UQ120 직접 조회(`DGM_NM LIKE '%상록수%'`)와 `presentSn` 일치. **cleanup 사업검색 "상록수아파트 재건축정비사업/강남구"와도 DGM_NM+SIGNGU_SE(11680)로 조인 일치**.
- **주의: 응답의 `shape` 좌표는 TM 중부원점(약 x=200,000~220,000 / y=440,000~450,000)** — WGS84로 변환 필요(proj4js, EPSG:5186/2097 → 4326).

### 경로 B — ArcGIS 직접 조회 (전체 덤프·조건 조회)
- 프록시 URL 패턴:
  `https://urban.seoul.go.kr/proxy/proxy.jsp?http://98.33.2.225:6080/arcgis/rest/services/UPIS/20200526_WFS/MapServer/<layerId>/query?where=...&outFields=...&returnGeometry=true&outSR=4326&f=pjson`
- 파라미터: `where`(표준 SQL, `LIKE '%..%'` 지원), `outFields`, `returnGeometry`, `outSR=4326`(→WGS84 lon/lat), `f=pjson|geojson`. **`resultRecordCount` 미지원**(400 "Pagination is not supported") — 페이징 없이 전량 반환(전체 덤프는 1회 요청이면 됨).
- 실측 레이어 (WFS MapServer, 총 280):
  | id | 이름 | 건수 | 비고 |

  | 12 | UPIS_C_UQ120 | 2,964 | **정비사업(전 유형)** — 전량 덤프 18.7MB(필드 2개·outSR=4326·f=pjson) |
  | 63 | UPIS_C_UQ111 | 8,331 | 지구단위계획/정비구역 계열 |
  | 3 | UPIS_C_UQ151 | 17,161 | |

  - WMS MapServer(357)는 세분 레이어: `UPIS_C_UQ120_BZ101`~`BZ606`(id 94~122). 지도 UI가 `searchGeometry(title)`로 이 이름을 id로 매칭해 조회. 실측: `UPIS_C_UQ120_BZ101` 조회 227건 = UQ120 ATRB_SE=BZ101 카운트와 일치.

### 신속통합기획 전체 데이터 (경로 C — 가장 단순)
- WMS 레이어 94 = `UPIS_C_UQ120_BZ101`, 한 번의 WFS 쿼리로 전량 수신 가능 (실측 227건, 1.07MB GeoJSON):
  `.../20200526_WFS/MapServer/94/query?where=1%3D1&outFields=*&returnGeometry=true&outSR=4326&f=geojson`
- 실측 구성: 25개 자치구 전역, 기획완료(PP0103) 132 + 추진중(PG01) 95. **모든 필드가 LCLAS_CL=BZ100 계열.**
- 신통기획 데이터가 현재 matjip `redevelop_seoul.json`의 '신통' 분류(사업명 regex 판별)보다 **정확·완전** — 사업명 매칭 없이 코드(BZ101)로 확실히 구분됨.

### matjip 자동 수집 설계 제안
1. cleanup 사업검색(`lsubBsnsSttus.do` 순회) → 사업장명·자치구·진행단계
2. 통합검색 API(`classifyType=bsns`)로 사업명→`presentSn`/`dgmAr`/`tnBsnsPropels`(추진단계)/폴리곤 획득
3. 전체 갱신이 필요하면 UQ120(L12) 덤프 1회 → 사업명·자치구로 cleanup 목록과 조인, shape를 4326으로 변환해 저장
4. 좌표계: ArcGIS `outSR=4326` 결과는 그대로 WGS84(네이버 지도 호환). 통합검색 API shape만 TM→4326 변환
5. 신속통합기획 전용 데이터는 경로 C(`BZ101` WFS 1회)로 별도 갱신이 가장 간단.

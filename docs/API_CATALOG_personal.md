# 공공데이터포털 활용신청 카탈로그 — 개인 참고자료

> **이 파일은 사용자 개인 자료다.** `AGENTS.md` 읽는 순서에 넣지 않았고, AI 가 코드를 쓸 때
> 참조하지 않는다. AI 가 참조하는 것은 `API_SCHEMA.md` 뿐이다.
>
> **왜 분리했나**: 호출해 본 적 없는 API 의 스키마는 추측이 섞인다. 그런데 AI 는 문서에 적혀
> 있으면 믿고 검증을 건너뛴다 — 틀린 스키마는 없는 것보다 나쁘다. 실제 사례로, AI 메모리에
> "청약홈 3종 승인됨"이라고 적혀 있어서 실제 90건인 걸 모르고 몇 턴 동안 그대로 말했다.
> 그래서 **AI 가 쓰는 문서(API_SCHEMA.md)에는 실측한 것만** 넣고, 전체 목록은 여기 둔다.

## 목록 갱신 방법 (다음에 다시 뽑을 때)

data.go.kr 로그인 후 마이페이지 > 활용신청 현황(`/iim/api/selectAcountList.do`).
기본 10건씩 페이지가 쪼개지는데, 폼에 hidden input 을 넣으면 한 번에 나온다:

```js
// 브라우저 콘솔
const f = document.getElementById('searchVO');
['pageUnit','recordCountPerPage','pageSize'].forEach(n => {
  let i = f.querySelector(`input[name="${n}"]`);
  if (!i) { i = document.createElement('input'); i.type = 'hidden'; i.name = n; f.appendChild(i); }
  i.value = '100';
});
f.querySelector('input[name="pageIndex"]').value = '1';
f.setAttribute('onSubmit', ''); f.setAttribute('action', '/iim/api/selectAcountList.do');
f.submit();
// 로드된 뒤
[...document.querySelectorAll('.apply-result-item')].map(e => {
  const t = e.innerText.replace(/\s+/g, ' ').trim();
  const m = t.match(/\[(승인|신청|보류|반려)\]\s*(.+?)\s*계정/);
  return (m ? m[1] : '?') + ' | ' + (m ? m[2] : t.slice(0, 70));
}).join('\n');
```

⚠️ 목록의 링크는 `uddi:` 와 내부 PK 만 담고 있어서 **데이터셋 번호(15xxxxxx)가 없다.**
번호는 각 상세 페이지에서 확인해야 한다. 세션은 자주 만료된다.

## 5. 공통 제약 (기획할 때 감안할 것)

- **인증키가 계정당 하나다.** `DGK` 를 쓰는 수집기를 동시에 돌리면 합계가 일 한도(개발계정
  10,000)를 넘겨 데이터가 조용히 비워진다. 2026-08-22 에 서울 12개 구를 잃었고, 이후
  `tools/dgk_lock.js` 로 코드에서 막았다.
- **오류가 HTTP 200 에 실려 온다.** 쿼터 초과·스로틀링도 200 이라 '0건'과 구분되지 않는다.
  수집기는 반드시 오류를 구분해야 한다.
- **`DGK` 는 Encoding 키**(`%` 포함)다. curl `--data-urlencode` 로 넘기면 이중 인코딩되어
  승인된 API 도 401 이 난다.
- **운영계정**은 활용사례 등록 시 트래픽 증액이 가능하다. 서비스로 키울 때 필요.
